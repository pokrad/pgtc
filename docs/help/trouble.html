Troubleshooting

Keys that do nothing, a screen that looks wrong, connections that fail, and answers to the questions that come up most.

If a key does not work

pgtc only gets the keys your terminal passes on. Every terminal keeps some key combinations for itself — to switch its own tabs, to scroll, to change the input language — and some cannot tell certain combinations apart at all. This is the most common surprise in any terminal program.

Three things always help:

  1. Use the second key. The commands that are often affected have one — see the table.
  2. Use the menu. F9 (or Esc 9) reaches nearly every command.
  3. Give the command another key in keymap.toml.

Terminals that pass every key. Terminals with the “kitty keyboard protocol” — kitty, WezTerm, foot, Ghostty, recent Alacritty, iTerm2 when it is enabled — report all of these keys exactly as pressed; pgtc switches the protocol on by itself. The Windows console and Windows Terminal also report most of them.

PuTTY

Alt + arrows work with PuTTY's default settings. In PuTTY 0.77 and newer you can also choose Terminal → Keyboard → Arrow keys with modifiers: xterm-style.

Finding out what a key does

Press F1: if the key is in the list but pressing it does nothing — or something else — the terminal is keeping or changing it. If it is not in the list, the command is not available where you are.

Questions and answers

“New query” and “Open SQL file” are disabled

A query tab needs a database. Put the tree cursor on a database — or on anything inside one — on a connected server. On a server row, a role or a tablespace there is no database to open the tab for.

F7 says “No developer templates”

The templates are not installed yet: Settings → Install templates, or pgtc --setup on the command line.

F7, F4 or autocomplete say I should finish or close the result first

The tab has a paused result — its label shows 1,000+ rows — or an export is running. The tab's connection is busy with it. Press Alt+End to fetch the remaining rows, or Alt+Shift+C to end the result; then try again. See Large results.

A statement says it “cannot run inside a transaction block”

A script of several statements is sent as one piece and runs as one transaction. VACUUM, CREATE DATABASE, CREATE INDEX CONCURRENTLY, ALTER SYSTEM and a few others cannot do that. Select just that statement and press F5 — with Auto commit on.

My script failed in the middle. What was changed?

Nothing — unless the script contains its own COMMITs. PostgreSQL runs a script sent as one piece as one transaction and rolls all of it back on an error. Fix the statement the error points to and run the script again.

Every statement answers “current transaction is aborted”

The tab has Auto commit off and a statement failed: the transaction is in the failed state (the status row says Transaction failed – rollback). Choose Query → Rollback. To have pgtc do that by itself, turn on Query → Auto rollback on error.

I created a table but the tree does not show it

The tree shows what it loaded. Put the cursor on the schema (or on Tables) and press Ctrl+R.

Autocomplete does not offer a new table or column

Each query tab reads the names once. It reads them again after that tab runs a CREATE / ALTER / DROP, and after a refresh of the tree (Ctrl+R there). Do one of the two.

Copy does not reach my clipboard over SSH

Over SSH the text travels to your machine through your terminal (“OSC 52”). The terminal must support it and allow it — Windows Terminal, iTerm2, kitty, WezTerm and Alacritty do; in some it is a setting (iTerm2: Applications in terminal may access clipboard; tmux: set -g set-clipboard on). In pgtc, OSC 52 clipboard must be on in Settings. If your terminal cannot do it, select the text with the terminal itself: hold Shift and drag.

Paste with Ctrl+V pastes something old (over SSH)

Over SSH, Ctrl+V can only reach the clipboard of the remote machine or pgtc's own buffer. To paste what you copied on your machine, use the terminal's paste: Ctrl+Shift+V, Shift+Insert or the right mouse button.

Where did my exported file go?

To the machine pgtc runs on, into the folder shown in the dialog's Folder: line. Over SSH that is the server; fetch the file with scp or sftp.

I cannot select text with the mouse to copy it out of the terminal

pgtc uses the mouse itself. Hold Shift while you drag and the terminal selects as usual.

A SQL file does not open because it is not UTF-8

pgtc reads SQL files as UTF-8. Convert the file, for example: iconv -f WINDOWS-1250 -t UTF-8 old.sql > new.sql.

The profiler does not start

  • logging_collector is off — set logging_collector = on in postgresql.conf and restart the server. pgtc does not restart servers.
  • Missing rights — you need to be a superuser, or to have pg_read_server_files and the right to run ALTER SYSTEM.
  • A managed cloud database — usually neither is possible there.

See SQL profiler.

pgtc asks about “logging settings” when I connect

The profiler was running when pgtc last ended without being able to stop it, and the server still logs every statement. Answer Yes to put the settings back. See If pgtc could not put the settings back.

The dashboard shows “-” for some values, or no query text for other sessions

PostgreSQL shows those details only to superusers and to members of pg_monitor. Ask for that role: GRANT pg_monitor TO your_user;

Cancel or terminate in the dashboard is refused

You may signal your own sessions; for others you need to be a superuser or a member of pg_signal_backend. Sessions of superusers can only be ended by superusers.

Can I change a table / drop an object with a dialog?

No — pgtc writes SQL for you to review instead. To change an object: Ctrl+E on it (Edit in new query tab). To create or drop one: F7 (developer templates). To write statements for a table's rows: F4 and gti, gtu, … (generate commands).

Can I edit the rows of a result in the grid?

No. The grid is for reading and copying. Change data with UPDATE / INSERT / DELETE; gtu table on F4 writes the statement with every column for you.

Can I see the query plan?

Put EXPLAIN or EXPLAIN (ANALYZE, BUFFERS) in front of the statement and run it: the plan is the result set. (Remember that EXPLAIN ANALYZE really executes the statement.)

How do I move my settings to another machine?

Copy settings.toml and keymap.toml from the config folder and the themes and developer_templates folders from the data folder — see Files and folders. Passwords are in .pgpass.

The log file

pgtc never prints messages onto the screen it draws on. What it has to report goes into a log file, one per day, in the logs folder of its data folder:

PlatformLog folder
Linux~/.local/share/pgtc/logs
macOS~/Library/Application Support/pgtc/logs
Windows%APPDATA%\pgtc\logs

The files are named pgtc.2026-11-16.log; the last 7 are kept. For a problem you can repeat, start pgtc with more detail and look at the end of today's file:

PGTC_LOG=debug pgtc                 Linux, macOS
$env:PGTC_LOG="debug"; pgtc         Windows PowerShell
set PGTC_LOG=debug && pgtc          Windows cmd

PGTC_LOG=pgc_db=trace logs only the database layer, in full detail.
